# VoxPopuli
[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](https://github.com/samdoom-coder/voxpopuli/blob/main/LICENSE)

A self-contained **digital-world simulator** that predicts how the public reacts to a news story.

Feed it a headline and a piece of news; VoxPopuli spins up a crowd of AI citizens with
personalities, stances and social ties, lets them talk, react to breaking events, form
camps, and drift with the crowd — then produces a **smart prediction report** of where
public opinion lands, how confident the prediction is, and who the key influencers are.

---

## Quick start

Requires Python 3.10+ and Node 18+.

```bash
cd voxpopuli
npm install          # installs the root helper package (only once)
npm run setup        # installs backend deps + builds the frontend
npm run dev          # starts FastAPI on :8787 (serves the built UI)
```

Open http://127.0.0.1:8787, create a project with a headline + news text, tune the crowd
size and rounds, and run the simulation.

### With an LLM key (optional, recommended for richer behavior)

Create `.env` next to `.env.example`:

```
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL_NAME=gpt-4o-mini
PORT=8787
```

Set `LLM_API_KEY` and restart. The engine detects it on startup (`/api/health` reports
`llm_mode: "llm"`) and uses batched LLM calls for citizen reasoning; leave it empty for the
built-in heuristic engine. Any OpenAI-compatible endpoint works.

## Architecture

```
frontend/   React + Vite SPA (2D world canvas, sentiment chart, live feed, report view)
backend/    FastAPI + SQLite + simulation engine
  app/
    main.py        app factory, CORS, static serving, router mounts
    routes.py      REST API (/api/*) + WebSocket (/ws/{sid})
    config.py      env-driven config, LLM detection, caps
    db.py          SQLite schema + CRUD (projects, sims, agents, messages, events, snapshots, reports)
    agents.py      world generation: LLM persona batches (or heuristic fill), agent layout
    simulation.py  the engine: run loop, per-round actions, community pull, snapshots
    knowledge.py   topic/entity extraction + summarization from the input news
    llm.py         OpenAI-compatible client with chat_json / batched gather + fallbacks
    report.py      prediction report (markdown): LLM-generated or heuristic fallback
    ws.py          live WebSocket broadcasting to dashboards
  tests/           pytest smoke suite
scripts/           setup.sh / backend.sh helpers (Colab-friendly, system-Python fallback)
```

### Simulation engine

Each round every active citizen decides to post, reply, like or stay quiet based on their
persona, current stance and mood, the recent conversation context, and any active breaking
news. After each round, passive citizens are pulled toward the influential voices
(social contagion), snapshots are recorded, and the dashboard is updated live over
WebSocket.

In **heuristic mode** behavior is generated by a fast built-in rule engine; in **LLM mode**
behavior comes from batched parallel LLM calls (index-aligned fallback keeps the run going
even if the model mangles names).

### Breaking events

POST `/api/simulations/{sid}/events` with `{content, impact}` at any time. The event is
injected into the next round, biases the whole crowd's sentiment and stances, and appears
in the round payload broadcast to connected dashboards.

### Prediction report

On completion the app writes a markdown report: executive summary, net sentiment movement,
key drivers, camp breakdown, top influencers, confidence assessment and caveats.

## API overview

| Method | Path | Purpose |
| ------ | ---- | ------- |
| POST | `/api/projects` | create a project (name, requirement, seed news) |
| GET | `/api/projects` / `/api/projects/{pid}` | list / detail |
| POST | `/api/projects/{pid}/extract` | knowledge extraction (topics, entities) |
| POST | `/api/simulations` | create a simulation (num_agents, rounds, speed_ms) |
| GET | `/api/simulations` / `/api/simulations/{sid}` | list / detail |
| POST | `/api/simulations/{sid}/build` | generate the citizen world |
| POST | `/api/simulations/{sid}/run` | start the engine |
| POST | `/api/simulations/{sid}/stop` | stop mid-run |
| POST | `/api/simulations/{sid}/events` | inject a breaking event |
| GET | `/api/simulations/{sid}/{messages,snapshots,events,agents}` | data for the dashboard |
| GET/POST | `/api/simulations/{sid}/report` | prediction report |
| POST | `/api/simulations/{sid}/analysis` | camps + sentiment series summary |
| WS | `/ws/{sid}` | live round/action/status feed |

---

## Simulation configuration

- `num_agents` — crowd size (default 40; 8–200)
- `rounds` — how many rounds of conversation (default 12)
- `speed_ms` — delay between rounds; `0` = as fast as possible (default 0)
- `mode` — `auto` (use LLM if key present), `llm`, or `heuristic`

## Development

```bash
npm run backend    # run the API alone
npm run frontend   # run the Vite dev server (proxies /api and /ws to :8787)
npm run build      # rebuild frontend/dist
cd backend && python3 -m pytest tests/ -q   # backend tests
```

The dev Vite server proxies `/api` and `/ws` to `127.0.0.1:8787`, so no CORS fiddling is
needed in development.
